# به‌روزرسانی خودکار NexDesk

برنامه نسخه جدید را از `https://nexdesk.ir/updates/windows.json` می‌خواند، امضای آن را بررسی می‌کند، دانلود را داخل خود برنامه با درصد انجام می‌دهد و نسخه فعلی را جایگزین می‌کند.

## ۱. ساخت کلید امضا (یک‌بار)

```bash
pip install pynacl
python tools/nexdesk_update/publish.py --keygen --key-id 2026-11
```

خروجی، مسیر کلید خصوصی و خط آماده‌ی زیر را چاپ می‌کند:

```
NEXDESK_UPDATE_PUBKEY = 2026-11:<64 hex>
```

آن را در **GitHub → Settings → Secrets and variables → Actions → Variables** به‌عنوان متغیر `NEXDESK_UPDATE_PUBKEY` ثبت کنید. این کلید عمومی است و در بیلد تعبیه می‌شود؛ بدون آن، آپدیتر عمداً خاموش می‌ماند.

کلید خصوصی (`~/.nexdesk/update-signing.key`) را از مخزن دور نگه دارید و از آن نسخه‌ی پشتیبان بگیرید. اگر گم شود، کلاینت‌های منتشرشده دیگر به‌روزرسانی نمی‌پذیرند.

## ۲. انتشار یک نسخه

```bash
# 1) نسخه را در Cargo.toml و Cargo.lock و pubspec بالا ببرید، بیلد بگیرید
# 2) مانیفست را بسازید و امضا کنید
python tools/nexdesk_update/publish.py \
  --exe dist/NexDesk-1.5.4-x86_64.exe \
  --key 2026-11:%USERPROFILE%/.nexdesk/update-signing.key \
  --notes-fa notes.fa.txt --notes-en notes.en.txt \
  --min-supported 1.5.0 \
  --out site/updates/windows.json
```

- `--mandatory` نسخه را اجباری می‌کند (پنجره اصلی قفل می‌شود).
- `--min-supported 1.5.0` هر کلاینتی پایین‌تر از این نسخه را هم مجبور به آپدیت می‌کند، حتی بدون `--mandatory`.
- نسخه، حجم و SHA-256 از خود فایل خوانده می‌شوند؛ چیزی را دستی وارد نکنید.

## ۳. آپلود روی سایت

```
https://nexdesk.ir/updates/NexDesk-1.5.4-x86_64.exe
https://nexdesk.ir/updates/windows.json
```

مانیفست باید با `Cache-Control: no-store` سرو شود، وگرنه کلاینت نسخه‌ی قدیمی را می‌بیند. نمونه برای nginx:

```nginx
location = /updates/windows.json {
    add_header Cache-Control "no-store, max-age=0";
    types { }
    default_type application/json;
}
```

## ۴. بررسی پیش از انتشار

```bash
python tools/nexdesk_update/publish.py --verify site/updates/windows.json \
  --pubkey 2026-11:<64 hex>
```

## رفتار کلاینت

| حالت | رفتار |
|---|---|
| بررسی | ۲۰ ثانیه بعد از اجرا، سپس هر ۶ ساعت؛ تلاش مجدد ۲۰ دقیقه بعد از خطا |
| آپدیت اختیاری | دیالوگ با «بعداً» و «نصب»؛ تعویق فقط برای همان نسخه |
| آپدیت اجباری | پنجره اصلی قفل، بدون دکمه بستن و بدون Esc؛ اتصال جدید رد می‌شود |
| جلسه فعال | قطع نمی‌شود؛ نصب پس از پایان آن یا با تأیید صریح |
| دانلود | نوار پیشرفت + درصد + مگابایت؛ انصراف فقط در حالت اختیاری |
| نصب | نسخه نصب‌شده: UAC و جایگزینی در Program Files / نسخه پرتابل: استخراج مجدد و ری‌استارت |
| خطا | «تلاش دوباره» + «دانلود دستی»؛ فایل نیمه‌کاره هرگز نصب نمی‌شود |

## امنیت

- امضای Ed25519 روی یک متن متعارف (نه JSON خام) — تغییر فاصله یا ترتیب کلیدها امضا را نمی‌شکند.
- SHA-256 و تطابق دقیق حجم فایل قبل از نصب.
- رد کردن نسخه پایین‌تر از نسخه نصب‌شده و مانیفست قدیمی‌تر از آخرین مانیفست دیده‌شده.
- بدون کلید عمومی، آپدیتر اجرا نمی‌شود؛ مسیر «بدون بررسی» وجود ندارد.

## چرخش کلید

1. کلید جدید بسازید: `--keygen --key-id 2027-03`.
2. کلید عمومی جدید را به متغیر `NEXDESK_UPDATE_PUBKEY` اضافه کنید (با کاما جدا شود) و یک نسخه منتشر کنید که هر دو کلید را می‌شناسد.
3. دو نسخه را دو-امضایی منتشر کنید: `--key 2026-11:... --key 2027-03:...`.
4. سپس کلید قدیمی را از متغیر حذف کنید.
